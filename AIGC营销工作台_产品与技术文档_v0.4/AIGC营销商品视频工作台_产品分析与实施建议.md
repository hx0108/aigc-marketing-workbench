# AIGC 营销商品视频工作台：产品分析与实施建议

> 文档性质：基于本次讨论和 GitHub 公开资料整理的产品分析与方案，供后续验证和设计使用。不是已经完成的 PRD、代码实现或用户验证报告。
>
> GitHub 项目与 Star 信息为 2026-10-23 的检索快照，功能主要依据仓库公开说明，未对各项目进行统一部署、源码审计或成片对比。项目状态、平台规则、模型能力和价格可能变化，选型前应重新核实。

## 一、产品目标与定位

建设一个**面向电商商家和运营人员的多平台商品视频工作台**。用户上传商品图片和相关资料后，工具辅助提炼商品卖点、生成脚本与分镜，结合配音、字幕、配乐和视频合成，产出适合抖音与小红书发布的商品营销视频。

建议先跑通“一个商品，从资料上传到抖音、小红书两版成片”的完整流程，再根据实际使用情况扩展批量生产。

产品希望向用户兑现的价值：

> 上传一次商品资料，持续产出适合不同平台、方便修改的营销视频。

第一版用户与使用场景的工作假设：

- 用户：中小电商商家、店铺运营、内容运营人员。
- 商品：先选一个熟悉、资料清楚、适合展示的品类，例如家居日用品；具体品类尚待确定。
- 端形态：中文网页工作台。
- 首要结果：基于同一份商品资料，生成可编辑、可导出的抖音和小红书两版视频及配套发布素材。

上述定位和用户价值仍需通过商家访谈、样片测试和真实使用验证。

### 值得优先评估的项目

- **ClipForge**：重点研究商品库、卖点提炼、分镜、局部重做及带货成片流程。
- **MoneyPrinterTurbo**：重点研究素材处理、配音、字幕、合成、API 和任务管理。
- **Pixelle-Video**：重点研究图像、视频、语音能力组合与自定义素材流程。
- **短视频工厂**：重点研究已有实拍素材的批量混剪体验。
- **AdCraft**：重点参考广告创意、资产与分镜工作流的交互方式。

这些判断基于公开资料，不表示已确认上述项目满足本产品的质量、安全或交付要求。最终选型应使用相同商品和素材进行测试。

### 许可与复用边界

- ClipForge、短视频工厂和 MoneyPrinterV2 的仓库标注为 AGPL-3.0；具体复用与交付方式需结合许可文本审查。
- MoneyPrinterTurbo 的仓库标注为 MIT；其依赖、模型、音乐、字体和素材的授权应分别核对。
- OpenShorts 的核心应用与 `cloud/` 目录采用不同许可，应核对目标版本及涉及目录的实际条款。
- Atlas Marketing Studio 在检索时 README 声称 MIT，但未找到根目录 `LICENSE`，GitHub 许可证字段为空；代码复用前应向权利人确认。
- 商业使用前应重新核实目标版本的许可证、依赖、第三方服务条款以及素材权利。本节不是法律意见。

## 三、产品与开源项目的区别

当前设想中的商品图上传、卖点提炼、脚本分镜、配音字幕、视频合成、平台导出及部分局部重做能力，已有开源项目公开提供。不能仅凭这些功能宣称产品具有独特性。

建议把差异化建立在一条完整的运营工作流上：

**商品资料 → 可追溯的商品档案 → 双平台创意方案 → 可控生成 → 低成本修改 → 版本与效果记录。**

### 1. 商品创作档案

一次整理商品信息，并在后续创作中复用：

- 保存商品名称、型号、规格、价格、适用场景和已确认卖点。
- 记录每个事实来自哪份资料或用户输入，并保留资料版本。
- 区分不同规格对应的图片与描述；缺失、冲突和待确认内容需要明确显示。
- 保存用户认可的展示素材、品牌表达，以及用户主动确认的创作偏好。
- 商品信息变化时，提示哪些历史脚本、字幕或封面使用了旧信息，由用户决定是否更新。

AI 可以提出候选事实和卖点；系统不应把模型推测直接当成已经验证的商品事实。例如仅凭外观图片，不能确定商品材质、容量、认证或实际效果。

### 2. 同一商品生成两套可解释的平台创意

平台选择应影响创意目标、脚本、镜头顺序、字幕节奏、封面和发布文案。用户能并排查看两版方案，理解它们为什么不同，并按需复用素材或同步卖点。

以下是待验证的初始创意假设，并非平台算法规则或流量保证：

| 维度 | 抖音版本 | 小红书版本 |
|---|---|---|
| 内容入口 | 具体问题、场景或视觉动作引入商品 | 具体需求、选购问题或生活场景引入商品 |
| 信息组织 | 聚焦一个核心利益点，展示过程 | 说明适用人群、使用方式、细节和边界 |
| 镜头 | 更紧凑的展示与信息切换 | 为细节、使用步骤和说明留出时间 |
| 文案 | 短句、直接、适合口播 | 自然表达，兼顾商品与场景关键词 |
| 配套输出 | 视频封面、标题、简短发布文案 | 视频封面、标题、笔记正文 |

示例：同一款桌面收纳盒，抖音版本可围绕“桌面小物总找不到”展示整理过程；小红书版本可围绕“小桌面如何分区收纳”，说明尺寸、隔层和摆放方式。两版应共用已确认的商品事实，不能自动编造“亲测”“使用一个月”等体验。

平台上传规格、商业内容、AIGC 标识和各类目限制，应在开发前分别核对最新官方规则，维护来源和更新时间；本次讨论尚未完成两平台规则的全面核实。

### 3. 局部修改与版本比较

- 修改价格、字幕或配乐时，尽可能复用已生成画面，只重新执行受影响的合成步骤。
- 单镜不满意时，允许替换或重做该镜，保留已认可镜头和旧候选。
- 允许复用主体内容，对开头、卖点或封面制作少量可比较版本。
- 修改前展示受影响范围、可复用素材及预计新增费用；实际收费以服务商结果为准。
- 保存版本及依赖关系，支持查看差异和回退。

局部修改不是独占功能。差异应通过实际操作时间、成本和可用性对比证明。

### 4. 后续运营反馈

先记录用户主动采纳、修改和退回的脚本与镜头；经用户确认后，形成店铺创作偏好。后续可允许用户手动录入或通过获授权接口导入发布数据，将商品、平台、创意版本和结果关联。

效果比较需保留样本量、账号、投放预算、发布时间等条件，不能直接将不同环境下的播放或成交差异归因于脚本。数据授权和接口可用性均需单独验证。

## 四、用户流程

```text
上传商品资料
  → AI 解析与候选卖点
  → 用户确认商品信息
  → 选择平台、营销目标和视频形式
  → 生成两版脚本与分镜
  → 用户审阅并修改
  → 生成素材、配音、字幕与配乐
  → 合成、预览与局部修改
  → 导出成片及平台发布素材
```

| 阶段 | 用户操作 | 系统职责 |
|---|---|---|
| 上传资料 | 上传商品图、产品介绍或说明文件 | 提取文字与图片信息，记录原始文件及来源 |
| 确认商品 | 修改商品信息和候选卖点 | 显示缺失、冲突及待确认信息，保存确认版本 |
| 设置创作 | 选择平台、受众、目标、形式和时长 | 应用可维护的创作策略，生成预算估计 |
| 审阅方案 | 比较并修改双平台脚本和分镜 | 给每镜安排文案、画面、时长、素材来源与生成方式 |
| 生成与合成 | 确认执行、查看进度、预览 | 执行模型调用、配音、字幕、混音和视频合成 |
| 修改和导出 | 修改局部内容，下载成片 | 保留版本，导出视频、封面、标题和发布文案 |

建议第一版文件输入明确限定为 JPG、PNG、PDF、DOCX 和纯文本；每个项目先对应一个商品及其明确规格。具体限制应通过文件处理能力验证后确定。

商品信息确认和分镜审阅是两个重要检查点：前者减少事实错误，后者避免对不满意的创意进行付费视频生成。

## 五、视频形式与生产方式

| 视频形式 | 首选生产方式 | 重点 |
|---|---|---|
| 产品特写 | 真实商品图与裁切、平移缩放、背景和文字动画 | 清晰呈现商品、包装、Logo、颜色和规格 |
| 图文混剪 | 商品图、用户视频、文字卡片、转场和配音组合 | 降低生成与修改成本，便于稳定产出 |
| AI 场景生成 | 商品参考图生成场景关键帧，再生成短动态镜头 | 先检查关键帧，再逐镜检查动态效果和商品外观 |

一条视频可以混用三种方式。建议先做好产品特写与图文混剪，并以受控范围验证少量 AI 场景镜头。

直接使用原图合成与通过模型生成商品画面有不同的保真边界；AI 场景可能改变外观、文字或包装，不能承诺商品绝对不变形，应提供预览与替换能力。

## 六、技术实施建议

### 1. 选型原则

建议自建商品资料、平台策略、任务和版本管理，通过明确接口评估并接入现成的视频生成与合成能力。也可先用合适的开源项目验证需求，再决定是否二次开发；选择受许可证、目标部署方式、实际代码质量及团队能力约束。

不要仅依据 Star 选择基础项目。对候选项目使用同一组商品资料、同等创作目标和相近预算，比较商品准确度、内容质量、修改便利性、稳定性、耗时和实际成本。

### 2. 推荐的基础结构

- **网页端**：商品资料、创作设置、双平台分镜、成片预览和导出。
- **业务服务**：用户、商品、项目、任务、版本、权限和额度。
- **后台任务进程**：文件解析、模型调用、配音和视频渲染。
- **数据库与文件存储**：保存结构化数据、原始文件、生成素材及成片。
- **模型适配层**：首期选择可验证的文本、图像、视频和语音服务，统一记录任务与结果。
- **视频合成**：优先评估 FFmpeg 完成剪接、字幕、混音和编码。

AI 负责提出卖点、脚本、分镜和候选素材；权限、任务状态、费用、幂等、重试和版本由确定性代码管理。

### 3. 必要行为约束

- 对重复提交使用幂等控制，避免重复创建付费任务。
- 保存外部任务标识；结果不明时先查询或对账，不能直接假定失败并重复提交。
- 服务中断后可恢复任务状态和已完成素材。
- 修改只触发受影响阶段，保留旧候选与已确认成片。
- 商品事实、脚本、分镜和素材保持版本关联，方便追溯。
- 未配置或未验证的模型能力应明确报错；Mock 成功不代表真实模型已验证。

## 七、分阶段推进

| 阶段 | 主要内容 | 验收重点 |
|---|---|---|
| 样片验证 | 选择一个品类与 5～10 个真实商品，尝试候选开源项目和生成方式 | 商品准确度、双平台差异、运营可接受度、修改时间与实际费用 |
| 首版闭环 | 资料上传、商品确认、双平台脚本分镜、产品特写、混剪、配音字幕和导出 | 用户能独立完成两版视频，并修改受影响部分 |
| 场景与规模 | 增加 AI 场景、单镜候选、批量变体、品牌模板和效果记录 | 商品保真、任务恢复、成本上限和版本比较 |

首批建议选择包装清晰、卖点可核实、容易展示的日用品或家居商品；这只是初始建议，最终应结合用户实际商品和素材选择。

## 八、验证与决策标准

建议同一商品、同一素材、相近预算，比较本产品与候选工具：

1. **商品事实**：抽查规格、价格、名称、卖点和包装是否与已确认资料一致，记录错误与人工修正。
2. **成片可用性**：运营人员能否接受画面、中文配音、字幕、节奏和平台版本差异，记录采用与退回原因。
3. **人工时间**：记录从上传资料到两版成片可用的操作时间，以及修改一个镜头或字幕的时间。
4. **成本与耗时**：记录成功、失败、重做的模型费用及合成耗时；按最终可用成片核算成本。
5. **恢复能力**：验证文件解析失败、模型调用失败、任务状态不明、中断恢复及重复提交。
6. **发布结果**：如有真实发布，记录可获得的播放、互动、点击或成交；保留账号、投放条件与样本量，避免无依据的因果结论。

当前没有已经完成的对比测试、真实用户验收或营销效果数据。指标目标值应在样片和首批试用后确定。

## 九、当前建议的下一步

1. 确定首个商品品类，准备真实、获授权的商品图和说明资料。
2. 用同一商品测试 ClipForge、MoneyPrinterTurbo 和 Pixelle-Video 的相关路径，记录成本、耗时与错误。
3. 形成“同一商品 × 两个平台 × 产品特写、图文混剪、AI 场景”的样片矩阵；按预算分批执行。
4. 让真实运营人员审阅商品事实、双平台脚本和成片，观察修改行为。
5. 根据证据决定是否复用开源代码、首版功能边界、所需模型和后续 PRD。

核心判断：优先证明“商品信息准确、双平台方案有实际区别、修改省时省钱”，再扩展批量生产。
